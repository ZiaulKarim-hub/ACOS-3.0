# Workbook Schemas — Internal + Buyer-Facing

The skill produces **two distinct workbooks** (plus a separate markdown QA
report). Each is generated at a different phase and serves a different
audience.

## At a glance

| Artifact | Generated by | Worksheets | Audience |
|---|---|---|---|
| **Internal Working Workbook** (`<Name>_Internal_Working_<Date>.xlsx`) | `build_excel_guide.py` (Phase 9) | 4 | OKOA associate / boss reviewing the data room |
| **Buyer-Facing Index** (`<Name>_Index_<Date>.xlsx`) | `build_buyer_index.py` (Phase 11, after finalization) | 2 | External counterparty (loan buyer / participant / takeout lender / property buyer / foreclosure bidder) |
| **QA Report** (`<Name>_QA_Report_<Date>.md`) | `build_qa_report.py` (Phase 9) | (markdown file) | OKOA associate — diagnostic only |

The buyer-facing index is **derived from the boss-finalized internal
workbook**, so it cannot leak any internal reasoning, confidence scores, or
exclusion list — by construction.

---

## Visual-Grouping Pattern (Applies to WS 2, WS 3, and WS 4 Section B)

All three data-bearing worksheets in the internal workbook share the same
visual treatment for folder hierarchy columns:

1. **Sort:** rows are sorted first by Primary Subfolder, then by Sub-folder, then by Sub-sub-folder, then by filename / document-type.
2. **Repeat suppression:** within each primary group, the Primary Subfolder cell is populated only on the *first* row; subsequent rows leave that cell blank. The same suppression applies to Sub-folder within a primary group, and to Sub-sub-folder within a sub-folder group.
3. **Excel outline grouping:** every row whose Primary Subfolder cell is suppressed gets `outline_level = 1`. This makes Excel render a +/− gutter button at the left that collapses each primary group to its single visible header row. `summaryBelow = False` and `summaryRight = False` are set so the visible row is at the *top* of each group, not below.
4. **Empty sub-sub-folder column:** if no row in the worksheet populates the Sub-sub-folder column, that column is hidden via `column_dimensions[col].hidden = True`. Dynamic — a deeper-nested taxonomy keeps the column visible.

When the buyer-facing index workbook is built (Phase 11 / `build_buyer_index.py`),
it reads the boss-finalized internal workbook and **forward-fills** the
suppressed values before sorting (the values are still semantically present;
the suppression is purely visual). The buyer workbook then re-applies the
same suppression + outline pattern for consistency.

## Internal Working Workbook

### Worksheet 1 — Cover

Free-form layout (column A: labels, column B: values). Single-page-feel.

Sections:
- **Title** — `Data Room — <DataRoomName>` + "Internal Working Workbook" subtitle
- **Run Information** — Date prepared, Run ID, Source folder, Deal type, Objective
- **Cover Information** — counts: files in source folder, files included, files excluded, missing/recommended
- **How to Navigate This Data Room** — Overview paragraph + **per-primary-folder summary list** for every primary subfolder actually used in Worksheet 2. Each line: humanized folder name + one-sentence summary of what's in it for this deal type. Summary text comes from `FOLDER_SUMMARIES` in `build_excel_guide.py`, keyed by deal type and category number.
- **Workbook Legend** — one-line description of each of the 4 worksheets, including a hint about the +/− gutter button on data worksheets.
- **Footer note** — "This workbook is for internal use only."

**Cover does NOT contain:**
- Key Risks callout (moved to Worksheet 4)
- AI Confidence Summary (lives only in the standalone QA markdown — no duplication)

No tables, no dropdowns.

### Worksheet 2 — Files Included

The data room contents — every file going into the room.

| Col | Header | Description |
|---:|---|---|
| 1 | Primary Subfolder | Top-level data-room folder, humanized (e.g., `01 — Default & NOD`) |
| 2 | Sub-folder | 2nd-level folder, humanized (e.g., `01.01 — Default Declaration Letter`) |
| 3 | Sub-sub-folder | 3rd-level folder if any; usually blank for foreclosure_auction |
| 4 | Original Filename | Source filename verbatim |
| 5 | Proposed Renamed Filename | Per `references/naming_convention.md`: `[Cat#].[Sub#]_DocType_Borrower-or-Property_Date_Status.ext` |
| 6 | Brief Description | 1–3 sentences, snippet-backed |
| 7 | Why Included | Why this file belongs in this folder for this deal type |
| 8 | Confidence — Reasoning | Numeric, 0.00–1.00. Confidence in the col-7 reasoning. |
| 9 | Confidence — Overall Row | Numeric, 0.00–1.00. Pessimistic minimum across (classification, extraction, summary, OCR) confidences. Traffic-light fill: ≥0.85 green, ≥0.70 amber, <0.70 red. |

Sort: by Primary Subfolder → Sub-folder → Sub-sub-folder → Original Filename.
Frozen header row, autofilter on row 1.

### Worksheet 3 — Files Excluded

Files the skill recommends withholding from the data room. Driver's licenses,
privileged communications, superseded versions, etc.

| Col | Header | Description |
|---:|---|---|
| 1 | Primary Subfolder | Where it would have gone if included |
| 2 | Sub-folder | Same |
| 3 | Sub-sub-folder | Same |
| 4 | Original Filename | Source filename |
| 5 | Proposed Renamed Filename | What the renamed name would have been |
| 6 | Reason for Exclusion | Reason category + reasoning (e.g., "Contains PII. Document is a driver's license with full name, DOB, address, and license number — exposing borrower identity to external parties without redaction.") |
| 7 | Confidence — Reasoning | Numeric, 0.00–1.00 |
| 8 | Confidence — Overall Row | Numeric, 0.00–1.00. Same traffic-light fill as WS 2. |

The sensitivity log (a separate tab in earlier designs) is absorbed here —
every sensitivity-driven exclusion appears with reasoning + confidence in cols
6–8.

### Worksheet 4 — Risks & Missing Documents

**Combined worksheet.** Top section: Key Risks. Bottom section: Missing or
Recommended Documents. Separated by spacer rows.

#### Section A — Key Risks

Up to 10 deal-type-specific risk dimensions sorted by severity (critical →
low). Severity column is fill-colored (red / orange / yellow / green). Five
columns:

| Col | Header | Description |
|---:|---|---|
| 1 | Severity | critical / high / medium / low (uppercase, color-filled) |
| 2 | Risk Category | e.g., "Notice Compliance", "Redemption Rights" |
| 3 | Risk Description | One-sentence description of the risk |
| 4 | Evidence Summary | What the skill found (or didn't find) in the source files |
| 5 | Recommended Action | What to do about it |

Pulled from `intermediate/risk_dashboard.json`.

#### Section B — Missing or Recommended Documents

Documents the skill expected based on the deal-type checklist but did not find
in the source folder. Each row is a recommendation: "you don't have this,
here's where it would go, here's why having it would matter."

| Col | Header | Description |
|---:|---|---|
| 1 | Primary Subfolder | Humanized folder name from `taxonomy_<deal_type>.md` (e.g., `03 — Notice of Sale`) |
| 2 | Sub-folder | Item ID + short title (e.g., `03.01 — Notice of Sale Recorded`) |
| 3 | Sub-sub-folder | Usually empty — auto-hidden if so |
| 4 | Document Type Expected | Item description from the deal-type checklist |
| 5 | — | Placeholder dash (no file exists) |
| 6 | Why It Would Strengthen the Data Room | Why-it-matters from the checklist |
| 7 | Confidence — Reasoning | Numeric (mapped from checklist severity: critical→0.95, high→0.85, medium→0.70, low→0.55) |
| 8 | Confidence — Overall Row | Numeric. Set to 0.60 by default to reflect sample-induced uncertainty when extraction was run on a subset. |

Sorted by primary subfolder then sub-folder.

## Buyer-Facing Index Workbook

Generated in Phase 11 (`create-room`) **after** the boss finalizes the
internal workbook. Reads only the `Files Included` worksheet of the internal
workbook — by design, it cannot accidentally include reasoning, confidence,
exclusions, or missing-document data.

### Worksheet 1 — Cover

Sanitized version. Sections:

- **Title** — `Data Room — <DataRoomName>`
- **Deal Information** — Date prepared, Transaction type, Objective, Total documents
- **How to Navigate This Data Room** — paragraph; same narrative as internal cover but trimmed to remove anything internal-only
- **Counterparty Notes** — boilerplate disclaimer ("This data room represents OKOA's good-faith compilation… Counterparty is responsible for independent verification… Nothing constitutes a warranty…")

No risks, no sensitivity, no QA, no confidence scores, no internal narrative.

### Worksheet 2 — Data Room Index

Table of every included file. **5 columns only:**

| Col | Header |
|---:|---|
| 1 | Primary Subfolder |
| 2 | Sub-folder |
| 3 | Sub-sub-folder |
| 4 | File (renamed name only — original name not shown) |
| 5 | Brief Description |

No reasoning, no confidence, no original filenames, no skill metadata.

Sort: by folder hierarchy.

## Standalone QA Report (Markdown)

`<DataRoomName>_QA_Report_<YYYY-MM-DD>.md`

Generated alongside the internal workbook. Plain markdown, intended for
internal review only. Not part of the buyer-facing data room. Sections:

1. **Header** — file purpose statement + run information (date, run ID, source, deal type, objective, file counts)
2. **Executive Summary** — one paragraph summarizing whether the AI's work held up
3. **Pass-by-Pass Findings** — 8 sections (7 standard QA passes + adversarial), each with flagged-count, total-checked, and resolved file-name list for any flagged file IDs
4. **No-Hallucination Check** — list of any unable_to_verify claims surfaced from per-file evidence bundles
5. **Rows Flagged for Your Attention** — table of files with overall row confidence below 0.70, with file name, confidence value, and a one-line note on why
6. **Methodology Notes** — what the AI couldn't do this run (e.g., "vision unavailable"), what that means for reliability, sample-induced uncertainty, aggressive-privileged-marking caveat
7. **Footer**

Markdown chosen for: readability in any editor, browser/IDE rendering, prose-friendly for narrative findings, future-proof format.

## What This Schema Replaces

The earlier 13-tab design (Risk_Dashboard, Tailored_Diligence_Scope,
Proposed_Data_Room_Index, Source_File_Manifest, Missing_Documents_And_Gaps,
Internal_Only, Sensitivity_And_Redaction_Log, Data_Tape_Check,
Duplicate_And_Version_Check, QA_Report, Final_Creation_Instructions,
Change_Log, README) is fully retired. Mapping to the new design:

| Old tab | New location |
|---|---|
| README | Cover (WS 1) of internal workbook |
| Risk_Dashboard | Risks & Missing Documents (WS 4), Key Risks section |
| Tailored_Diligence_Scope | Distributed across WS 2 (present items) and WS 4 (absent items) |
| Proposed_Data_Room_Index | Files Included (WS 2) of internal workbook |
| Source_File_Manifest | Eliminated as workbook tab; full manifest still lives at `intermediate/file_manifest.json` |
| Missing_Documents_And_Gaps | Missing or Recommended (WS 4) |
| Internal_Only | Files Excluded (WS 3) |
| Sensitivity_And_Redaction_Log | Absorbed into Files Excluded (WS 3) — every sensitivity-driven exclusion is here with reasoning |
| Data_Tape_Check | Absorbed into Files Included (WS 2) — the loan/payoff tape file appears as a normal row |
| Duplicate_And_Version_Check | Eliminated as workbook tab; duplicate detection still happens in scan; duplicates appear as separate rows in WS 2 |
| QA_Report | Standalone markdown file |
| Final_Creation_Instructions | Eliminated; the SKILL.md and `create-room` CLI handle this |
| Change_Log | Eliminated; diff log still produced by `validate_guide.py` but written to a separate JSON in intermediate/ rather than as a workbook tab |
