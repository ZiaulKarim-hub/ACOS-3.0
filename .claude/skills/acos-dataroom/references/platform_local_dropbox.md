# Platform — Local Folders + Dropbox-as-Synced-Folder

The skill operates exclusively on local file paths in v1. Dropbox folders are
treated as **local folders that happen to sync** — the skill does not call
the Dropbox API, does not authenticate, and does not initiate uploads. It
writes to a path; if that path lives inside `~/Dropbox/...`, Dropbox's own
sync agent handles propagation.

---

## What "Local" Means Here

Any path the OS can write to:
- Local disk: `/Users/zee/Documents/...`
- Synced folders: `/Users/zee/Dropbox/...`, `/Users/zee/Library/CloudStorage/Dropbox/...`, OneDrive, Box, iCloud Drive, Google Drive Stream
- External drives: `/Volumes/MyDrive/...`
- Network shares (with caveats below)

The skill cannot tell the difference between local and synced from path alone,
nor does it need to. Sync, if any, is the OS / sync agent's job.

---

## Source Folder Considerations

**Source folder may be on a synced platform** (often is). Implications:

- **Read latency:** files may be cloud-only (file references not yet hydrated). Dropbox Smart Sync, OneDrive Files On-Demand, and iCloud Optimize Storage all do this. The skill must trigger hydration before reading. On macOS, hydration happens automatically on `open()` — the read just blocks until the file is local. Long reads should not be misinterpreted as failures.
- **File system events:** sync activity may modify timestamps (modified date) without modifying content. The skill keys off SHA-256 hash, not modified date — so this is fine, but `Source_File_Manifest.modified_date` may not be the *original* modified date.
- **Lock conflicts:** if Dropbox is currently syncing a file, reads may briefly fail. The skill retries reads up to 3 times with 1-second backoff before flagging as inaccessible.

## Output / Working Directory

`<source>/_acos_dataroom_output/<run_id>/` is created inside the source folder
by default. **This means working artifacts also sync** if the source is in a
synced folder.

Pros: collaborator can see runs in progress; runs are backed up.
Cons: large extraction artifacts (rendered PDFs, image dumps) consume sync
bandwidth.

The user can override with `--output /local/path` to keep the working dir
local-only and only the final data room synced.

## Target Folder for `create-room`

`--target` is a regular path. Examples:

```
# Synced
--target "/Users/zee/Dropbox/DataRooms/AscentParkCity"
--target "/Users/zee/Library/CloudStorage/Dropbox/DataRooms/..."

# Local-only
--target "/Users/zee/Documents/DataRooms/AscentParkCity"

# External drive
--target "/Volumes/Backup/DataRooms/..."
```

The skill creates the target if it doesn't exist. If it exists and is non-empty, the skill **errors out** unless `--allow-non-empty-target true` is passed. This prevents accidental overlay onto an existing data room.

---

## Permissions Checklist (Generated by `create-room`)

After Phase 11, the skill writes `<target>/PERMISSIONS_CHECKLIST.md` with:

- Confirm folder permissions on `--target` allow the intended audience.
- For Dropbox: verify the target folder is shared correctly with the intended buyer / counterparty in the Dropbox UI. **The skill never sets sharing permissions itself.**
- Verify Smart Sync / Files On-Demand setting matches your intent. If buyers should download (not just stream), ensure the folder is set to "Available offline" before sharing the link.
- For local-only targets: this is a folder for *your* workflow only — generate a Dropbox link manually after copying the folder up.

---

## Network Share Caveats

For SMB / NFS shares mounted at `/Volumes/...`:

- **File hashing:** SHA-256 over network is slow but works. For large folders (> 5 GB), expect minutes.
- **OCR / vision:** PIL / pdfplumber read entire file into memory; large files over slow shares may exceed the per-file 300s timeout. The skill flags `extraction_timeout` and continues.
- **Atomic writes:** target folder writes use `os.rename()` from a temp filename, which on some network filesystems is non-atomic. The skill writes to a `.partial` extension and renames on success. Don't share the data room link until `create-room` reports success.

---

## What the Skill Does NOT Do

- ❌ Authenticate with Dropbox / Google / OneDrive / Box APIs
- ❌ Generate sharing links
- ❌ Set file or folder permissions
- ❌ Send notifications to counterparties
- ❌ Upload to a cloud storage API directly
- ❌ Copy to anything other than a local file path

Anything cloud-related happens *outside* this skill, by the sync agent or by
the boss manually.
