# User Guide Writing Skill

## Purpose

This skill provides structured guidance for creating user documentation that is clear, helpful, and accessible to the target audience.

## When to Use

Apply this skill when:
- Creating end-user documentation
- Writing help content
- Creating onboarding guides
- Writing tutorials
- Documenting features for users

## Skill Protocol

### Phase 1: Audience Analysis

1. **Identify your audience:**
   - Who will read this?
   - What's their technical level?
   - What do they already know?
   - What are they trying to accomplish?

2. **Define scope:**
   - What topics to cover?
   - What level of detail?
   - What to exclude?

### Phase 2: Structure Planning

1. **Organize content:**
   - Logical flow
   - Progressive complexity
   - Task-based organization

2. **Plan sections:**
   - Getting started
   - Core features
   - Advanced topics
   - Troubleshooting

### Phase 3: Writing

1. **Write clearly:**
   - Use simple language
   - Be concise
   - Use active voice
   - One idea per sentence

2. **Show, don't just tell:**
   - Include examples
   - Add screenshots
   - Provide step-by-step instructions

### Phase 4: Review

1. **Review for clarity:**
   - Can a new user follow this?
   - Are steps complete?
   - Are examples helpful?

2. **Test the instructions:**
   - Follow your own guide
   - Have someone else try it
   - Fix any gaps

## Writing Checklist

### Content

- [ ] Audience clearly defined
- [ ] Scope appropriate
- [ ] Topics logically organized
- [ ] All features covered

### Clarity

- [ ] Simple language used
- [ ] Technical terms explained
- [ ] Steps are numbered
- [ ] Examples provided

### Usability

- [ ] Easy to navigate
- [ ] Searchable
- [ ] Quick reference available
- [ ] Troubleshooting included

## Writing Guidelines

### Language

| Do | Don't |
|----|-------|
| Use "you" | Use "the user" |
| Use active voice | Use passive voice |
| Use simple words | Use jargon unnecessarily |
| Be specific | Be vague |
| Use present tense | Use future tense |

**Examples:**

| Instead of | Write |
|------------|-------|
| "The button should be clicked" | "Click the button" |
| "The user can utilize the feature" | "You can use this feature" |
| "The system will process your request" | "Your request is processed" |
| "In order to" | "To" |

### Formatting

1. **Use headings** to organize content
2. **Use bullet points** for lists of items
3. **Use numbered lists** for sequential steps
4. **Use bold** for UI elements and important terms
5. **Use code formatting** for commands and code
6. **Use screenshots** to show UI elements

### Screenshots

Best practices:
- Crop to show only relevant area
- Highlight important elements (arrows, boxes)
- Use consistent styling
- Include captions
- Keep file sizes reasonable

## Quality Checklist

Before publishing:

- [ ] Spelling and grammar checked
- [ ] All links work
- [ ] Screenshots are current
- [ ] Steps tested and accurate
- [ ] Consistent formatting
- [ ] Accessible (alt text, clear contrast)

## Output: User Documentation

When completing documentation work, ensure:

1. Content is accurate and complete
2. Language is clear and appropriate for audience
3. Examples work correctly
4. Navigation is logical
5. Formatting is consistent
