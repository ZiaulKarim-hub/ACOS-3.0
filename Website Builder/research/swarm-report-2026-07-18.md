## Executive Summary

**The target is measurable, and nobody is shooting at it.** "Award-quality" is not mystical: Awwwards publishes an exact weighted rubric (Design 40%, Usability 30%, Creativity 20%, Content 10%), scoring mechanics (>=18 jurors, 3 outliers dropped, Honorable Mention >= 6.5), and its winners share a standardized technique stack (three.js/WebGL + GSAP ScrollTrigger + smooth scroll + kinetic custom type + one "signature moment"). Nine independent agents confirmed the rubric; six confirmed the winner formula. Meanwhile the competitive landscape has a structural vacancy: no shipping AI builder competes on award-tier visual output (Agent 06), no purely AI-generated site has ever won Awwwards recognition (though hand-designed no-code Framer sites have — the medium is not the barrier, the generation process is), and the incumbents' own marketing admits sameness is their unsolved weakness. A design-first ACOS builder would create a fourth market tier, not enter a crowded one.

**The enemy is statistical, and the cure is upstream constraint plus downstream verification.** Seven agents independently converged on the same diagnosis: LLMs regress to the median of their training data (Tailwind's `bg-indigo-500` literally turned the AI web purple), and unguarded generate-judge loops actively homogenize output because judges prefer low-perplexity "house style" (Agent 09). Prompting harder does not fix this. What fixes it, per the evidence: a mandatory concept/art-direction gate before any pixels (the elite-studio process — Obys, Locomotive, Awwwards Academy all sequence concept -> art direction -> build), a bespoke design-token system generated per project (LLM chooses ~12 taste parameters; deterministic algorithms derive hundreds of values; a lint wall makes off-token styling unbuildable), and a machine-checkable "anti-slop" deny-list — the 16 AI-design tells are enumerable and 54% of real Show HN pages trigger them, so rejecting them mechanically is a cheap, measurable differentiator no incumbent enforces.

**The QA loop is proven, but its failure modes are quantified and must be designed around.** The render -> screenshot -> judge -> revise loop is officially endorsed by Anthropic, roughly doubles quality metrics in the best published architecture (WebGen-Agent), and is already running in production inside ACOS (loan-doc visual verification, ultimate-designer Wigum loop, doc-design-qa blind reviewers). But the literature is equally clear about limits: gains plateau at 3-5 iterations; iteration is non-monotonic (ship the best checkpoint, not the last); zero-shot VLMs are near chance at absolute aesthetic scoring (judge must be pairwise/anchored/rubric-decomposed); LLM judge panels make correlated errors (9 judges ~= 2.2 effective votes — cap panels at ~3 and spend the savings on deterministic checks); screenshots are blind to motion (the exact dimension awards judge hardest); and naive loops grow cost quadratically (state-passing + prompt-cached design-system prefix keeps it near-linear). Every one of these has a concrete mitigation that fits ACOS primitives.

**The build is mostly assembly, not invention.** Agents 17-18 mapped the ACOS estate: the Wigum loop machinery, blind opus screenshot reviewers with STALL detection, the thin-router + phase-orchestrator pattern (loan-doc), design-system-forge as a ready-made art director, the Puppeteer harness with all its hard-won waits, and the genesis component registry all exist and port nearly 1:1. The genuinely new surface is small: a multi-viewport live-page screenshot harness, a web-specific award rubric, a token-spec -> CSS adapter, a motion/filmstrip verification channel (the only research-grade item), and dev-server/build orchestration. The recommended stack is settled and now entirely free: Astro 5 static + Tailwind v4 `@theme` tokens + GSAP (100% free since April 2025, AI-codegen explicitly permitted) + Lenis + three.js, with a React/MSW/re-themed-shadcn fork only for the app-shell site type. Licensing risk concentrates in fonts (three-tier policy required) and generated imagery (license manifest per asset).

**Recommendation:** build Architecture C from Agent 17 — a loan-doc-shaped router + phase orchestrators, fronted by a mandatory concept gate and design-system-forge, with a two-tier QA loop (sighted inner Wigum, blind outer gate), per-type presets for the three site types (marketing / game promo / app shell — which collapse into two build targets), and a v1 -> v3 ramp that defers WebGL and the app-shell preset until the marketing-site core proves out. The full blueprint is at the end of this report; every element traces to agent findings.

## Key Findings (Cross-Referenced)

### Finding 1: The award target is a published, weighted, cloneable rubric — Design 40 / Usability 30 / Creativity 20 / Content 10
- **Confidence:** Verified (confirmed by Agents 01, 02, 03, 04, 06, 12, 19, 20)
- **Summary:** Awwwards scores 0-10 on four weighted criteria; >=18 jurors vote over 5 days; the 3 scores furthest from average are dropped; Honorable Mention >= 6.5; SOTD = top-of-day. CSSDA uses UI 40 / UX 30 / Innovation 30 with WOTD > ~8.0. FWA is holistic 0-100 (500+ win-qualified jurors, min 20 votes) with an explicit experimental bias. The 30% usability weight means "gorgeous but hostile" is score-negative even by the awards' own math.
- **Cross-references:** Agent 02 is the deepest primary-source read (evaluation page, FAQ, annual-awards mechanics); Agents 01, 03, 04, 06, 12, 19, 20 independently fetched the same evaluation page. Agent 12 notes the outlier-trim maps directly onto ACOS multi-agent consensus patterns.
- **Sources:** awwwards.com/about-evaluation/ (primary, fetched by 7+ agents), cssdesignawards.com/about, FWA Medium/judging pages, webdesignawards.io comparisons.

### Finding 2: What separates 6.5 from 9: art direction with a point of view, directed motion choreography, one signature moment, real-device performance
- **Confidence:** Verified (pattern confirmed by Agents 02, 06, 12; performance leg empirically confirmed by Agent 15)
- **Summary:** Practitioner/juror commentary converges: winners are not decorated templates — every choice serves a single idea; motion has "a director, not just a library"; each winner has one signature interaction; and jurors test on real devices (a 3D hero at 18fps on mid-range Android does not win). Judges "recognize WordPress themes, Webflow templates and AI-generated layouts instantly." Recurring winner stack: three.js/WebGL, GSAP ScrollTrigger, scrollytelling, kinetic/variable type, page transitions, custom cursors/preloaders.
- **Cross-references:** Agents 02 and 06 cite the same two practitioner guides independently; Agent 12 corroborates from studio case studies (Locomotive, Obys, Active Theory); Agent 15's Lighthouse measurements prove the performance leg is real and achievable.
- **Sources:** hontran.dev, utsubo.com award guides; Awwwards case studies (Igloo Inc, Locomotive); Agent 15 first-party Lighthouse audits.

### Finding 3: An AI builder can realistically target SOTD/HM tier; SOTY tier requires custom-engine R&D
- **Confidence:** Probable (Agents 02, 06)
- **Summary:** Sites of the Year (Igloo Inc, Lando Norris) run bespoke rendering technology — UI rendered inside WebGL, custom shader pipelines, VDB volume-data compression. That is years beyond template assembly. SOTD/HM tier — craft + choreography + performance — is the honest, attainable ceiling for a generated site, and "first AI system whose output wins an Awwwards mention" is an open, claimable milestone (Framer no-code wins prove tool-built sites are not disqualified).
- **Cross-references:** Agent 02 (Igloo case study detail); Agent 06 (no-AI-winner evidence, Framer SOTD precedents).
- **Sources:** awwwards.com/igloo-inc-case-study.html, awwwards.com/websites/framer/, winner-category no-code pages.

### Finding 4: "AI slop" is an enumerable, machine-detectable fingerprint — and therefore a lintable hard gate
- **Confidence:** Verified (confirmed by Agents 04, 06, 07, 12, 14)
- **Summary:** The 16 catalogued tells (Inter everywhere, "VibeCode purple" indigo->purple gradients, three icon-topped cards, badge-above-H1 heroes, serif-italic accent words, stat banners, uniform 16px radii/24px padding, dark-mode low contrast...) were found by deterministic DOM/CSS analysis on 1,590 Show HN pages: 22% heavy slop, 32% mild, only 46% clean. A Reddit-mined dataset (3.2M posts scanned) confirms "they all look the same" at scale, discussion volume up ~150x from 2023 to 2024. Because the tells are deterministic, an "anti-slop lint" can reject generations mechanically — a gate no incumbent ships.
- **Cross-references:** Five agents independently cite the Krebs Show-HN analysis and/or the 925 Studios tell list; Agent 06 adds the vibecoded-design-tells repo; Agent 04 adds the versioned two-tier (permanent + rolling) dated-tells framing; Agent 12 turns it into a "distinctiveness = distance from defaults" score.
- **Sources:** developersdigest.tech AI-design-slop analysis, github.com/JCarterJohnson/vibecoded-design-tells, 925studios.co, axe-web.com, isthatvibecoded.com.

### Finding 5: Root cause of sameness is distributional convergence — the fix is upstream constraint injection, never "prompt harder"
- **Confidence:** Verified (confirmed by Agents 04, 06, 07, 09, 12, 13, 14)
- **Summary:** LLMs return the statistical median of their training corpus; striking sites feed the next training round, hardening defaults (an ~18-month distinctive->cliche feedback loop). Tailwind's 2019 indigo-500 default demonstrably propagated into "every AI-generated interface on earth is purple" (acknowledged by Tailwind's own creator). Additionally, autonomous generate-evaluate loops converge to generic motifs over iterations (Patterns/Cell study) — homogenization is loop-side as well as generation-side. The only evidenced mitigations are upstream: explicit design tokens, negative constraints, reference-driven briefs, forced multi-option divergence, curated non-default type/color systems.
- **Cross-references:** Seven agents; Agent 09 uniquely adds the judge-side mechanism (perplexity-driven self-preference = familiarity discount for house style); Agent 13 frames it strategically ("generation is commoditized; art direction is the moat").
- **Sources:** prg.sh, dev.to indigo-500 post-mortem, arXiv 2603.13036 (design homogenization), Patterns S2666-3899(25)00299-5, 925studios.co, axe-web.com.

### Finding 6: Elite-studio process is concept-first, and it is mechanically copyable: no pixels until a concept artifact exists
- **Confidence:** Verified (confirmed by Agents 12, 02; corroborated by 06, 13)
- **Summary:** Obys, Locomotive, and the Awwwards Academy curriculum all sequence: brief -> references (abstracted, never copied) -> written concept -> art direction -> build -> motion. Distinctiveness levers are concrete: type-as-identity (hard-ban default faces for display), restraint budgets (max 2 typefaces, ONE signature interaction motif repeated as a system), imagery direction specs, and a house library of motion primitives refined across projects (Active Theory's Hydra, Darkroom's Lenis/Satus). The pipeline gate: every downstream visual decision must cite the concept document.
- **Cross-references:** Agent 12 (primary, studio interviews + curricula); Agent 02 (jury-side confirmation that explained intentionality is rewarded); Agent 13 (2026 expert consensus: humans/encoded taste keep art direction); Agent 06 (the "finisher" role is the open market gap).
- **Sources:** Codrops Obys interview (Mar 2026), Obys curriculum, Awwwards Academy course, Locomotive/Kvell case studies, Active Theory Medium.

### Finding 7: The design system must be a first-class generated artifact: DTCG tokens JSON -> deterministic compilers -> CSS variables, with a lint wall
- **Confidence:** Verified (confirmed by Agents 11, 14, 19; failure-mode side by Agents 05, 07, 10)
- **Summary:** The W3C DTCG token format reached stable (2025.10) and natively covers color/type/spacing/duration/cubicBezier/transition — the whole design vocabulary in one JSON-schema-validatable file. Style Dictionary 4 / Terrazzo compile it deterministically to CSS custom properties and Tailwind v4 `@theme`. The architecture rule from Agent 11: the LLM chooses ~12 scalar taste parameters (OKLCH hue anchors, contrast targets, type ratio/poles, font mood, radius/density, motion expressiveness); algorithms expand them into full ramps (Leonardo contrast-solving, Utopia fluid-scale math, M3/Carbon-seeded motion matrices). Enforcement is off-the-shelf: stylelint-declaration-strict-value + token-file a11y lint + raw-value CI grep — the LLM physically cannot ship a hex code. Agents 05/07 show why: every incumbent's drift/monotony failures trace to tokens living implicitly in the model's output distribution; the vendors' own fixes (Lovable Design Systems, v0 Design Systems 2.0) are partial versions of exactly this.
- **Cross-references:** Agent 11 (deep primary-source verification incl. M3/Carbon motion token values from source); Agent 14 (Tailwind v4 `@theme` as the enforcement mechanism); Agent 19 (tokens as the shared spine across site types); Agents 05/07 (industry failure evidence); Agent 10 (tokens as cached prompt prefix — the biggest cost lever).
- **Sources:** designtokens.org 2025.10, styledictionary.com, github.com/adobe/leonardo, utopia.fyi, tailwindcss.com/docs/theme, hvpandya.com LLM design-systems case study, material-web + carbon source token files.

### Finding 8: Contrast is solvable by construction; color engine should run in OKLCH with a dual WCAG 2 AA + APCA gate
- **Confidence:** Verified (confirmed by Agents 01, 03, 11)
- **Summary:** Adobe Leonardo inverts palette design — declare target contrast ratios, solve for colors — making accessibility an input, not a check. OKLCH's perceptual uniformity makes algorithmic ramps look hand-tuned and makes hitting contrast targets computable. APCA is more accurate for the dark, cinematic palettes of award sites (and is what DesignChecker uses programmatically) but is not yet law; WCAG 2 AA remains the defensible floor — pass both. This single pipeline choice removes the web's #1 accessibility failure (low-contrast text: 83.9% of top-1M homepages) from output by construction.
- **Cross-references:** Agent 11 (Leonardo/OKLCH mechanics), Agent 01 (APCA thresholds Lc75/60/45, DesignChecker precedent), Agent 03 (WebAIM 83.9% + the "luxury = pale grey" trend critique).
- **Sources:** github.com/adobe/leonardo, evilmartians OKLCH, git.apcacontrast.com, webaim.org/projects/million, w3.org WCAG 2.2.

### Finding 9: The screenshot loop is the proven core mechanism — endorsed by Anthropic, doubled quality in WebGen-Agent, already in ACOS production
- **Confidence:** Verified (confirmed by Agents 07, 08, 09, 10, 17, 18)
- **Summary:** Blind (no-render) generation has a hard ceiling (~76/100 Design2Code visual fidelity for frontier models); feeding the rendered screenshot back measurably fixes what the same model got wrong. Anthropic's official best-practices document describes exactly the mock -> implement -> screenshot -> compare -> iterate loop. WebGen-Agent (the most complete published architecture) lifted Claude-3.5-Sonnet accuracy 26.4% -> 51.9% using VLM screenshot scores + a GUI agent walking the site + backtracking/select-best. ACOS already runs this loop in three shipped skills (loan-doc visual verification, ultimate-designer wigum-loop.py, doc-design-qa) — the website builder needs only a new screenshotter (Puppeteer is already a dependency).
- **Cross-references:** Agent 08 (research architectures), Agent 07 (failure-mode framing: most defects are missing-verification, not model-capability), Agent 09 (loop failure modes), Agent 10 (economics), Agents 17/18 (local production precedent + harness).
- **Sources:** anthropic.com claude-code-best-practices, arXiv 2509.22644 (WebGen-Agent), Design2Code 2403.03163, local SKILL.md files.

### Finding 10: Iteration plateaus at 3-5 rounds and is non-monotonic — cap loops, detect plateaus, checkpoint every iteration, ship the argmax
- **Confidence:** Verified (confirmed by Agents 08, 09, 10)
- **Summary:** Three independent evidence lines (Anthropic "2-3 iterations," 1D-Bench 3-4 iteration plateau, UI2Code^N +8pts over 5 rounds with ~1pt marginal by round 5; Self-Refine gains concentrated in round 1). Critically, later iterations sometimes regress: best-of-all-cycles beat always-take-last 17.8% vs 8.7% in one vision-guided pipeline, and WebGen-Agent's backtracking exists for the same reason. Grounded external feedback (screenshots) is what makes refinement work at all — refinement without the visual critique gained only 1.5%. HALT ladder (Agent 10): PASS threshold -> plateau (score flat 2 rounds -> accept best-so-far) -> hard cap (5/section, 10-15/page composite) -> budget ceiling with best-effort emission.
- **Cross-references:** Agents 08, 09, 10 arrived at the identical loop-control design from different literatures (agent architectures, judge failure modes, token economics). Matches ACOS's existing Wigum 5/10 convention (Agent 17).
- **Sources:** arXiv 2303.17651, 2602.18548, 2604.19750, 2604.05839, 2511.08195, anthropic.com best practices.

### Finding 11: Judge architecture: pairwise + anchored + rubric-decomposed; absolute zero-shot aesthetic scoring is near-noise
- **Confidence:** Verified (confirmed by Agents 01, 08, 09)
- **Summary:** UIClip showed zero-shot VLMs perform close to chance at absolute UI design-quality judgment; WebDevJudge found pairwise beats absolute Likert by >8pp, and even the best judge trails human experts 66% vs 85%. What works: reference-anchored comparison (vs approved comps / curated exemplar galleries), rubric-decomposed critique with per-dimension anchors and few-shot exemplars (UICrit: +55% with targeted few-shot), region-grounded critique (bounding boxes), and pairwise tournaments for the ship gate. Multi-dimensional scoring agreed with humans 69.5% vs 48.5% for single-score judging.
- **Cross-references:** Agent 08 (UIClip reconciliation), Agent 01 (UICrit/UI-Bench + Awwwards-mechanics-as-protocol), Agent 09 (WebDevJudge numbers, anti-sycophancy rule: judge verdicts are immutable inputs — never let the generator argue with the judge in-context).
- **Sources:** arXiv 2404.12500 (UIClip), 2510.18560 (WebDevJudge), 2407.08850 (UICrit), 2508.20410 (UI-Bench), 2604.05839.

### Finding 12: Ensemble judging helps less than advertised — correlated errors make 9 judges ~= 2.2 votes; cap panels at ~3 and diversify channels instead
- **Confidence:** Verified (Agent 09 primary; tempers recommendations by Agents 01, 02, 12)
- **Summary:** LLM judges share blind spots even across vendors (Claude x Gemini error correlation phi=0.603): a 2026 study measured a 22pp Condorcet gap between predicted and actual panel accuracy, with the best single judge matching or beating the full 9-judge panel, and near-zero added value beyond 5 judges. Panel unanimity on a distinctiveness criterion should raise suspicion (shared generic taste), not confidence. Budget guidance: <=3 judge passes; spend the savings on genuinely decorrelated channels — deterministic DOM/functional checks and placed human gates. This directly tempers the "clone the 18-juror Awwwards panel with K>=5 VLM passes" idea proposed by Agents 01/02/12 (see Conflicts).
- **Cross-references:** Agent 09 (measured evidence); Agent 10 corroborates economically (better judge model beat more judge tokens in Anthropic's data).
- **Sources:** arXiv 2605.29800 (Nine Judges, Two Effective Votes), orq.ai PoLL writeup, 2510.11822.

### Finding 13: The judge must see pixels, not code — but should be fed structured extracted evidence
- **Confidence:** Verified (Agents 09, 01; operational nuance is a synthesis)
- **Summary:** WebDevJudge's ablation: removing source code cost judges 4-5% while removing screenshots cost only ~1% — multimodal judges anchor on code, so a page can look broken while tidy code earns a pass. Withhold raw code from the visual judge. Separately, UICrit/DesignChecker evidence says grounded critique beats vibes: feed the judge structured facts (font inventory, palette usage table, spacing histogram, motion report) extracted by the deterministic layer. These are compatible: no source code, yes structured evidence. ACOS's doc-design-qa blind reviewer (screenshot + rubric only) already implements the strict version.
- **Cross-references:** Agent 09 (withhold code), Agent 01 (feed Layer-A evidence), Agent 17 (local blind-reviewer precedent).
- **Sources:** arXiv 2510.18560, 2407.08850, DesignChecker 2407.17681, local acos-doc-design-qa SKILL.md.

### Finding 14: Deterministic checks carry more of the load than the VLM — a two-channel gate is mandatory because stills certify broken interactivity
- **Confidence:** Verified (confirmed by Agents 01, 03, 07, 09, 20)
- **Summary:** A large fraction of "design quality" is computable without any model: type-lint (modular scale fit, measure 45-75ch, line-height bands, <=2-3 families), spacing/alignment lint (8pt grid, 5px alignment tolerance), token entropy (premium sites have few systematic values; slop has 30 grays), layout metrics (Ngo/Miniukovich balance/symmetry/whitespace), contrast (APCA/WCAG), axe-core (catches ~57% of a11y issues; six error categories = 96% of real-world failures), motion lint (transform/opacity only, duration bands, reduced-motion present), overflow/bounding-box checks per breakpoint. Meanwhile static screenshots pass dead nav menus and broken forms (static judging: 72% precision at 90% recall on feasibility) — so a deterministic functional channel (Playwright click-walk, console errors, link walker) is non-optional. The aesthetic-usability effect means impressionistic QA (human or model) systematically under-reports usability harm — verification must be mechanical wherever possible.
- **Cross-references:** Agent 01 (the full Layer-A catalog with published numeric anchors), Agent 03 (aesthetics-usability effect + gate list), Agent 07 (57% axe coverage), Agent 09 (two-channel precision/recall data), Agent 20 (six automatable checks = 96% of failures).
- **Sources:** DesignChecker, Project Wallace, deque.com 57% study, WebDevJudge, NN/g aesthetic-usability articles, webaim.org.

### Finding 15: Motion is the weakest verification channel and the strongest judging dimension — it needs its own spec'd, framed, capped channel
- **Confidence:** Verified (problem: Agents 01, 07, 08, 09, 17; v1 solution direction: Probable)
- **Summary:** VLMs recall aesthetic animations at 0.16 from frame sequences; single stills are blind entirely; no vendor or paper verifies rendered animation — an industry-wide gap. Award juries, meanwhile, treat motion choreography as a primary separator. The evidence-backed compromise: (1) motion is *designed as data* — a motion spec (durations/easings/stagger/choreography rules as DTCG tokens per M3/Carbon precedent) generated at concept time, with code checked against spec statically; (2) deterministic motion lint (compositor-only properties, duration bands, no `linear` on movement, reduced-motion honored, CLS during interaction); (3) filmstrip capture (3-5 frames at fixed timestamps via Playwright clock control, or scripted scroll states) judged as multi-image prompts with textual perceptual cues; (4) an interaction manifest (element -> expected hover/click/scroll behavior) walked with before/after screenshot pairs (the proven Interaction2Code technique); (5) a curated house library of motion primitives selected and parameterized per concept, rather than model-improvised animation (the Active Theory/Darkroom pattern — the library becomes the moat).
- **Cross-references:** Agent 09 (VLM animation blindness numbers), Agent 08 (filmstrip/AnimSpec/Remotion patterns, interaction pre/post capture), Agent 07 ("popcorn effect" + Motion AI Kit), Agent 01 (motion anchors + filmstrip proposal), Agent 12 (house motion library strategy), Agent 11 (motion tokens verified from M3/Carbon source), Agent 17 (gap confirmed locally — nothing in ACOS verifies animation).
- **Sources:** arXiv 2604.26148, 2411.03292, motion.dev/docs/ai-kit, github.com/iart-ai/motion-skills, M3/Carbon token sources.

### Finding 16: Section-level generation and critique beats whole-page — +15% visual similarity, cheaper loops, sharper VLM attention
- **Confidence:** Verified (confirmed by Agents 08, 10)
- **Summary:** DCGen's divide-and-conquer (segment -> generate per section -> assemble) yields up to +15% visual similarity on large pages; zooming into flagged regions (1.2-3x crops, drawn bounding boxes) recovers failed generations and improves fix rates 5-10%. Tall full-page captures get downscaled past model image-token limits, destroying the fine detail (1px borders, type rendering) that award polish lives in. Economically, regenerating one hero section (~2-4k tokens) beats regenerating a page (~15-30k). Full-page capture still runs — but only as a final compositional/rhythm check (1-2 rounds), after sections pass.
- **Cross-references:** Agents 08 and 10 cite the same papers independently from different lenses (quality and cost); matches loan-doc's section-fragment swarm + assembler shape (Agent 17).
- **Sources:** arXiv 2406.16386 (DCGen), 2411.03292 (Interaction2Code), 2602.05998.

### Finding 17: Loop economics: context accumulation is the cost driver; design system as cached prefix is the single biggest lever
- **Confidence:** Verified (Agent 10 primary; corroborated by Agents 08, 18)
- **Summary:** Naive loops re-bill accumulated context every round — a 10-cycle loop costs ~50x a single pass; multi-agent systems run ~15x chat tokens; token spend alone explains 80% of performance variance (Anthropic's own data), and a better model beat a 2x token budget. Rules that fall out: pass distilled state between rounds, never history; hold the design system + brief as an immutable cached prefix (0.1x reads; converts 30-page-site cost from ~3M prefix-tokens to ~330k effective); screenshot aggressively (rendering is ~free vs model time — use render-success as a pre-filter before spending vision tokens); resize QA screenshots <=1,568px long edge; declare effort tiers in the orchestrator (landing page = 1 agent; 5-page site = 2-4 page agents; 30-page = section-library + parallel page agents); parallel best-of-N only for the divergent concept phase (N=3-5 + tournament), serial refinement for convergent polish (Snell et al. compute-optimal mixing, up to 4x savings).
- **Cross-references:** Agent 10 (primary); Agent 08 (UI2Code^N: tight single-context loop beats agent-pipeline decomposition per page); Agent 18 (phase isolation in Claude Code: orchestrator holds only manifest + pass/fail state; noisy contexts die with subagents).
- **Sources:** anthropic.com multi-agent-research-system, arXiv 2408.03314, 2407.21787, 2511.08195, platform.claude.com vision docs.

### Finding 18: Single-context inner loop, multi-agent outer structure — the granularity resolution of an apparent architecture conflict
- **Confidence:** Verified (synthesis of Agents 05, 08, 09, 10, 17)
- **Summary:** Industry evidence (Agent 05): Lovable tried and abandoned multi-agent orchestration; Bolt is one prompt + Sonnet; v0 is one model + deterministic guardrail sandwich (dynamic RAG prompt, mid-stream token rewriting, post-stream AST autofixers). Research evidence (Agents 08-10): a tight render->screenshot->revise loop in one context is cheaper AND scores higher than planner/coder/reviewer decomposition per page; an agentic multi-stage judge underperformed single-shot judging. But role separation is proven where the goal is *taste enforcement and independence* (OneRedOak design-review agent, ACOS's Independence Wall, WebGen-Agent's separate judge). Resolution adopted by both Agents 08 and 17 independently: single-agent sighted inner loop per section/page; independent blind critic gates between milestones; multi-agent for parallelism across pages and for phase isolation — never for per-page quality.
- **Cross-references:** Agents 05, 10 (single-agent evidence); Agents 08, 17 (hybrid resolution); Agent 09 (judge separation is mandatory for gate integrity: never same model instance generating and gating).
- **Sources:** lovable.dev engineering blog, posthog Bolt piece, vercel.com v0 blogs, arXiv 2511.08195, 2510.18560, local ACOS skills.

### Finding 19: The v0 guardrail sandwich is the reliability recipe to replicate: pinned knowledge in, deterministic fixers out, "renders-or-it-didn't-happen"
- **Confidence:** Verified (Agent 05 primary; corroborated by Agents 07, 18)
- **Summary:** v0 optimizes one metric — % of generations that render without error (93.87% vs ~90% raw) — via versioned knowledge injection (chosen over web search to avoid stale/hallucinated data), streaming find/replace fixes (hallucinated icon names embedding-matched to real ones in ~100ms), and <250ms post-stream AST autofixers (dependency completion, provider-wrapping checks). Leaked prompts encode taste as hard mechanical rules ("exactly 3-5 colors," "NEVER purple unless asked," spacing-scale-only, token-only colors). Scale AI's hallucinated-image-URL fix was likewise deterministic AST rewriting after regex and LLM-based approaches failed. Transferable 80% for ACOS: pinned stack knowledge in skill prompts, a deterministic post-generation pass (import/asset/dependency validation against a real manifest), build-exit-zero + screenshot as the success definition.
- **Cross-references:** Agent 05 (v0/Bolt/Lovable internals), Agent 07 (Scale AI asset-hallucination case; vendor mitigation map — every incumbent converged on pieces of this, none shipped the full lattice), Agent 18 (local harness encodes the same philosophy: waits, lazy-strip, fonts.ready are all deterministic reliability fixes).
- **Sources:** vercel.com/blog/how-we-made-v0-an-effective-coding-agent, github.com/x1xhlol system-prompt leaks (corroborated across >=2 repos), hyper.ai Scale AI writeup.

### Finding 20: Recommended stack is settled and free: Astro 5 static + Tailwind v4 @theme + GSAP + Lenis + three.js; React/MSW/re-themed-shadcn only for app shells; avoid Next.js/Svelte/Angular
- **Confidence:** Verified (confirmed by Agents 14, 16; winner-stack fit by Agents 02, 06; per-type fork by Agent 19)
- **Summary:** Web-Bench measures React-flavored syntax at 60-65% pass@2 vs 25-55% for Vue/Svelte/Angular — reliability follows training density, and Astro components are ~95% HTML+JSX-like (inheriting the familiarity) while shipping zero JS by default. Tailwind v4's CSS-first `@theme` makes every token simultaneously a utility generator and a runtime CSS variable — the best machine-enforceable token mechanism available (and half a billion monthly downloads settles maturity). GSAP became 100% free April 2025 including SplitText/MorphSVG/ScrollTrigger, with AI-generated code explicitly permitted (proprietary no-charge license — pin versions, snapshot license text; the only restriction that matters is "don't build a competing visual animation tool"). Lenis wraps native scroll (accessibility survives; the de facto award-site standard). three.js is the healthiest large library measured (MIT, distributed authorship, same-day commits). ## Data Gaps

1. **No aesthetic quality-vs-iteration curve exists.** All plateau data (Self-Refine, UI2Code^N, Design2Code) measures fidelity-to-reference or correctness, not open-ended "wow" quality. Whether award-tier aesthetic quality plateaus at the same 3-5 rounds is unmeasured (Agents 08, 10).
2. **Motion verification is unvalidated end-to-end.** No controlled study shows frame-sequence/video feedback measurably improves generated animation quality; VLM judgment of full-page scroll narratives, WebGL scenes, and cursor interactions is unstudied (Agents 07, 08, 09, 17). This is the single largest engineering-risk area of the blueprint.
3. **No judge-side calibration experiment for bold vs generic.** The claim that VLM judges penalize distinctive design is inferred (weak aesthetic discrimination + familiarity bias); scoring known Awwwards winners vs competent-generic templates with candidate judge prompts would close it and appears unpublished (Agent 09). Cheap to run in-house during v1.
4. **No public dataset of award-site jury scores or SOTD technique census.** Awwwards exposes no API; UICrit is mobile-app biased; the genre reference gallery must be hand-curated (Agents 01, 02, 12). Gallery ToS for programmatic harvesting unverified (Agent 12).
5. **FWA criteria are opaque** — holistic 0-100, no rubric; only genre tendencies documentable (Agents 01, 02).
6. **What fraction of SOTD winners pass WCAG 2.2 AA is unmeasured** — an automated audit of winners would be a novel contribution and would calibrate the "award-tier AND accessible" claim (Agent 03).
7. **Field (CrUX) data for measured award sites unavailable** (API quota/key) — lab-only performance conclusions; also single-run Lighthouse numbers (Agent 15).
8. **ESRB/COPPA age-gate primary sources returned 403** — the neutral-age-screen requirement is industry common knowledge but needs a primary citation pass before the game-preset compliance copy is finalized (Agent 19).
9. **Per-site-type mobile/desktop splits are inference** — no public dataset splits mobile share for B2B marketing vs game promo vs SaaS app traffic (Agent 20).
10. **LLM adherence under token constraints has one self-reported case study** (418->0 violations) — no benchmark comparing styling drift with vs without token-only enforcement (Agent 11).
11. **Licensing follow-ups:** Fontshare FFL current version + font-serving clause gloss (manual browser check recommended); FLUX.2 per-variant terms; Veo paid-tier terms; Grilli Type (inferred, not fetched); AI-image provider ToS not fetched this session (Agents 13, 16).
12. **No per-round dollar figures for design loops** — cost estimates were composed from token-price primitives, not published benchmarks; likewise no in-repo token benchmarks for loan-doc/ultimate-designer runs to calibrate model tiering (Agents 10, 17).
13. **UI-Bench live leaderboard not fetched** — per-tool design-quality rankings of v0/Lovable-class tools remain unquantified here (Agent 07).
14. **Methodological note:** the swarm's shared 200-call WebSearch budget was exhausted mid-run; agents 15, 16, 18, 19, 20 (and parts of 12, 13) worked via direct WebFetch of known-authoritative URLs only — coverage is skewed canonical over exploratory for those topics. ## Recommended Build Blueprint

### Architecture choice — ACOS Hybrid C (Agent 17), granularity-corrected (Agents 05, 08, 10)

A thin router skill + phase orchestrator agents (the production-proven loan-doc shape), with three grafts: design-system-forge as the art-direction front end, doc-design-qa's blind reviewer + STALL machinery as the outer gate, and a genesis-lite component registry so site N+1 starts warm. Inside each phase, generation is a **single-context sighted loop** (the industry- and research-validated shape); **multi-agent exists only for phase isolation, parallel pages, and independent gates** (the Independence Wall). Rationale: fastest credible path (effort A < C < B), highest quality ceiling for art-direction-led sites (C >= A > B), and the registry pays for itself by site 3.

### Pipeline phases

**P0 — Brief intake** (router): site type -> per-type wizard fields; game type auto-mines the project repo (FruitSync: store copy, privacy policy, tone already on disk — Agent 19); B2B/B2C switch for marketing (Agent 20).

**P1 — Concept & art direction** (web-art-director): >=3 references -> abstracted attributes only (legal + creative rule, Agent 12); written concept doc (story, tension, POV, ONE signature moment, restraint budgets: <=2 typefaces, constrained palette, one repeated interaction motif); negative-constraint block (anti-slop deny-list + current saturated-template list, Agents 04/07/12); imagery-direction spec; then **render 3 art-directed hero variants and let the user pick** (show-don't-MCQ; gives the loop its concrete visual target — Agent 08's convergence prerequisite).

**P2 — Design system** (deterministic core): LLM emits ~12 parameters -> generators emit DTCG `tokens.json` (color via OKLCH + contrast-first solving; type/space via Utopia with the 200%-zoom check; motion duration/easing matrix + choreography rules; radius/density) -> compile to `tokens.css` + Tailwind `@theme` -> lint wall armed (stylelint strict-value, token-file a11y lint, raw-value grep). Font selection applies the three-tier license policy. The compiled system becomes the immutable cached prompt prefix for everything downstream (Agent 10's biggest lever).

**P3 — Content**: sitemap from the per-type section grammar (structure constrained, skin generative — Agent 19's Relume lesson); copy passes scannability + anti-hyperbole rules (Agent 20); trust/credibility slots enforced for marketing.

**P4 — Assets**: router per asset type (Recraft SVG icons/illustrations wired to tokens; raster hero per imagery spec; Ideogram for decorative lettering only; semantic text never in images); provider adapters + local persistence; license manifest per asset; AST validation of every reference against the manifest.

**P5 — Build** (web-build-orchestrator): scaffold from pinned template repo (`astro@5`, `tailwindcss@4`, `gsap`, `lenis`, optional `three`); parallel section builders emit fragments against tokens; assembler composes pages; interactivity in vanilla `<script>` GSAP modules; app-shell preset forks to Vite+React+MSW+re-themed shadcn with populated/empty/loading states.

**P6 — QA gauntlet** (order matters; each gate feeds concrete work items, not scores):
1. *Deterministic*: build exit-zero -> token lint -> slop lint -> axe (zero critical/serious) -> APCA+WCAG contrast -> type/spacing lint -> asset resolution -> motion lint (transform/opacity, duration bands, reduced-motion present) -> overflow/bbox per viewport -> functional click-walk + console-error + link-walker.
2. *Sighted inner Wigum, per section*: capture (deterministic profile: 390/768/1440, dSF 2, animations disabled, lazy neutralized, fonts ready) -> defect YAML -> fix -> recapture; cap 5, plateau exit, git checkpoint per iteration, crop-zoom on flagged regions.
3. *Blind outer gate, per page x viewport*: fresh opus reviewer, screenshots + rubric + lint evidence only; anchored 0-100 dimensions + pairwise vs the genre reference gallery (both orders; disagreement = tie); STALL rule; verdicts immutable.
4. *Motion channel (v2+)*: spec-vs-code static check -> filmstrip frames at fixed timestamps -> interaction-manifest walk with before/after pairs.
5. *Performance*: lhci median-of-3 metric assertions + budgets.json + runtime WebGL assertions (renderer.info draw calls, pixelRatio <=2) + GPU-tier ladder verification.
6. *Site-level*: cross-page consistency, pseudolocalization stress (+35% string expansion through the screenshot loop), reduced-motion render diff (must differ where motion exists, and still look designed).

**P7 — Delivery**: static `dist/` -> Cloudflare Pages (snapshot publish, manual republish); evidence bundle + scorecard + license manifest + font-license checklist; final human gate (the human is placed exactly where judges are weakest: motion feel, distinctiveness, interactivity feel — Agent 09).

### QA rubric skeleton (Agent 01's two-layer frame + Agent 20's per-type weights)

Layer A gates zero-out shipping (never traded against beauty). Layer B, 0-100, weights echo Awwwards with per-type deltas:

| Dimension | Marketing (B2C / B2B) | Game promo | App shell |
|---|---|---|---|
| Typography & hierarchy | 12 | 10 | 12 |
| Layout, grid & composition | 10 | 8 | 12 |
| Color & art direction | 8 | 8 | 8 |
| Imagery / graphic language | 6 | 10 (gameplay-with-UI required) | 4 |
| Detail polish (hover/focus/borders) | 4 | 4 | 8 |

| Creativity / distinctiveness / signature moment | 20 (hero crop double-weighted) | 24 (subordinate to <=30s genre-recognition test) | 12 (coherence over novelty) |
| Content presentation | 10 (trust checklist near-binary; scannability; B2B: pricing/spec transparency) | 10 (mechanical verbs; press kit present) | 12 (empty/loading states designed) |

Verdict bands: <55 regenerate; 65-79 HM-grade iterate; >=80 ship-eligible; ship additionally requires the pairwise gallery win-rate and all Layer A gates.

### Cost / loop-cap policy (Agent 10)
Effort tiers declared in the orchestrator: landing page = single agent; 5-page site = 2-4 page agents; 30-page = section library + parallel pages with 2-3 (not 5) iterations after the system freezes. State-passing between rounds, never history; design system + brief as cached prefix; screenshots <=1,568px long edge, ~8 per review batch; render-success pre-filters before any vision spend; best-of-N (N=3) only at concept stage; external hard budget caps (models cannot self-forecast spend).

### Licensing guardrails (Agents 16, 13, 12)
Vendor the GSAP license snapshot; pin exact versions + lockfiles, `npm ci` in generated CI; OFL fonts self-hosted with license files, Fontshare link-only, foundry faces -> launch checklist; Unsplash/Pexels with prohibited-use lints (no stock faces implying endorsement, no stock in logos); per-asset provenance manifest with indemnification class; commercially-safe mode pinning image generation to indemnified lanes; >=3-reference rule with pixel-discard enforced at P1.

### Phased build plan

**v1 — Marketing-site core (proves the thesis).** Router + 3 phase agents; concept gate with 3 rendered hero variants; token pipeline (DTCG -> @theme + lint wall); Astro static scaffold from pinned template; deterministic gate suite incl. slop lint; sighted Wigum (multi-viewport screenshot harness — the small Puppeteer delta) + blind opus outer gate with the web rubric; lhci performance gate; Cloudflare deploy. Motion limited to lint-verified CSS/GSAP presets from a starter library; no WebGL. *Build-new: screenshot harness, web rubric, token adapter, slop-lint script.* Run the judge-calibration experiment (winners vs templates) during this phase. Exit criterion: a marketing site that passes every gate cold and a designer cannot identify as AI-built at first look.

**v2 — Motion, game preset, assets, reuse.** Filmstrip + interaction-manifest motion channel; house motion-primitive library (Lenis/GSAP choreographies, curated and versioned — the moat asset); game-promo preset (platform CTA registry, presskit(), sound toggle, age-gate component) piloted on FruitSync with repo-mined brief; asset-generation routing + license manifest + AST asset validation; component/style registry (genesis-lite) + prompt-cache discipline for multi-page economics; hand-curated pairwise reference gallery per genre; pseudolocalization gate.

**v3 — App shells, spectacle, cockpit.** App-shell preset (Vite+React+MSW+re-themed shadcn; three-state screenshot coverage; latency-weighted rubric); WebGL/three.js hero modules from curated snippets + Gaussian-splat embed component + GPU-tier ladder scaffolding; live preview cockpit (ic-server port: SSE build state + JSONL feedback inbox); trend-context refresh feed (leading-gallery sampling + rolling avoid-list); optional cross-vendor judge for the distinctiveness axis; autopilot/eternity integration for unattended multi-hour builds; distinctiveness scorer (distance-from-defaults metric).
